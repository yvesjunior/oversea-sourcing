4 · Queueing & intensive load — the recommendation

OSI is already a queue-based producer/consumer system — web produces jobs, worker consumes them, pg-boss inside Postgres is the broker (SKIP LOCKED, retries, transactional enqueue). The recommendation is to keep that foundation and add isolation, backpressure, and explicit scaling knobs — not to adopt RabbitMQ or a Redis queue, which would add a second stateful service for throughput we will never need (the bottleneck is the Claude API's concurrency, not the queue).

Why not a broker now: RabbitMQ is a second database in every operational sense (volumes, backups, upgrades, failure modes) on a single self-hosted VM. pg-boss gives transactional enqueue for free — a request and its job commit in one transaction, which a broker only matches via an outbox pattern (a queue-in-Postgres anyway). pg_dump snapshots state and in-flight jobs together. The pattern is in place; heavier tech waits for a signal.

5 · Build order & carried debts

A
Prove the contract. Refactor global_web behind the connector interface + the coverage check. Immediate cost savings on every warm request; dissolves the research-inline deviation on the way (research moves to its own invocation path).

B
The enforcement backbone. requireRole + tenancy helpers (E2), then invitations, switcher, team screen, Paramètres panels. Unlocks Enterprise sales conversations.

C
Collections & commerce. data_source + supplier_source + bans + source_run + /interne/sources; first registry connector; then supplier_partner + tiers + banded ranking.

M
MVP1 cut, unchanged and still first in line: facilitation (« Engager », engagement queue) and supplier verification — the sourcing engine feeds them but does not replace them.

Debts we keep carrying DEBT

  • The daily-quota race — check-then-act; needs an advisory lock. The most concrete prod defect; small fix, should ride along with Phase A.
  • No rate limit on server functions or uploads — only /api/auth/* is covered.
  • In-memory rate-limit counters — fine on one web container; Redis when replicated.
  • No test suite — the connector contract is the best place to start one: each connector is independently testable by design.
  • storage.deleteFile never called; .docx/.xlsx attachments accepted but unread; showcase constants still behind /transactions.
